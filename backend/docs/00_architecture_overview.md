## مقدمه

پروژه **Printoo24 Backend** یک API جامع برای پلتفرم فروشگاهی آنلاین پرینتو ۲۴ است که با استفاده از Django REST Framework توسعه داده شده است. این پروژه با معماری لایه‌ای و سرویس-محور طراحی شده تا قابلیت نگهداری، تست‌پذیری و توسعه را به حداکثر برساند.

### 🎯 اهداف اصلی پروژه:
- ✅ ارائه APIهای RESTful برای کلاینت‌های مختلف (وب، موبایل)
- ✅ مدیریت کامل فرآیند فروش آنلاین
- ✅ یکپارچگی با سیستم‌های مختلف از طریق سرویس‌های ماژولار
- ✅ پشتیبانی از چند محیط (توسعه، تولید)
- ✅ قابلیت مقیاس‌پذیری و عملکرد بالا

1. **جدا بودن لایه‌ها**: هر لایه فقط با لایه زیرین خود ارتباط دارد

4. **ماژولار بودن**: هر اپلیکیشن مسئولیت مشخصی دارد

### توضیح هر بخش اصلی:

#### 1. پوشه `api/`
**نقش**: لایه ارائه‌دهنده API
- شامل تمام endpointهای REST API
- نسخه‌بندی شده برای backward compatibility
- هر نسخه شامل serializers و views مجزا است
- **مستندات مربوطه**: [مستندات API](./api/README.md)

#### 2. پوشه `apps/`
**نقش**: اپلیکیشن‌های اصلی Django
- هر اپلیکیشن یک بخش از عملکرد را پیاده‌سازی می‌کند
- شامل models، services، views و سرویس‌های اختصاصی
- **مستندات مربوطه**: [مستندات اپلیکیشن‌ها](./apps/README.md)

#### 3. پوشه `core/`
**نقش**: هسته مشترک و reusable
- مدل‌های پایه که در چند اپلیکیشن استفاده می‌شوند
- سرویس‌های مشترک
- Managerهای سفارشی
- **مستندات مربوطه**: [مستندات Core](./core/README.md)

#### 4. پوشه `backend/`
**نقش**: تنظیمات و پیکربندی پروژه
- فایل‌های settings برای محیط‌های مختلف
- تنظیمات Celery، WSGI، ASGI
- **مستندات مربوطه**: [مستندات تنظیمات](./settings/README.md)

## جریان داده در پروژه

### 1. جریان یک درخواست typical:

```
Client Request
    ↓
URL Router (urls.py)
    ↓
API View (api/v1/.../views/)
    ↓
Serializer (اعتبارسنجی ورودی)
    ↓
Service Layer (منطق تجاری)
    ↓
Manager/Repository (دسترسی به داده)
    ↓
Database (PostgreSQL)
    ↓
Response (JSON)
```

### 2. جریان یک عملیات پیچیده (مثال: ایجاد سفارش):

```
1. Client → POST /api/v1/order/create/
2. OrderView دریافت درخواست
3. اعتبارسنجی داده‌ها با Serializer
4. فراخوانی OrderCreateService
5. بررسی موجودی سبد خرید (Cart Service)
6. محاسبه قیمت نهایی (Calculator Service)
7. ایجاد سفارش در دیتابیس (Transaction)
8. کم کردن موجودی انبار (Product Manager)
9. ایجاد رکوردهای سفارش (Order Models)
10. ارسال اعلان به کاربر (Notification Service)
11. ثبت لاگ (Logger)
12. برگرداندن Response به کلاینت
```

### 3. جریان وظایف ناهمزمان (Celery):

```
Task Creation
    ↓
Celery Broker (Redis)
    ↓
Celery Worker
    ↓
Task Execution
    ↓
Result Backend (Redis)
    ↓
Database Update (در صورت نیاز)
```

**مثال‌های وظایف ناهمزمان:**
- ارسال ایمیل‌های تأیید حساب
- پردازش فایل‌های بزرگ Excel
- محاسبات آماری
- پاکسازی فایل‌های موقت

## فناوری‌های استفاده شده

### Backend Framework
- **Django 5.2**: فریم‌ورک اصلی
- **Django REST Framework**: برای ساخت APIهای RESTful
- **Django Filters**: برای فیلتر کردن داده‌ها

### Authentication & Security
- **Simple JWT**: احراز هویت با توکن JWT
- **django-cors-headers**: مدیریت CORS
- **django-ratelimit**: محدودیت نرخ درخواست

### Database & Cache
- **PostgreSQL**: دیتابیس اصلی
- **Redis**: کش و صف پیام (Celery Broker)

### Task Queue
- **Celery**: اجرای وظایف ناهمزمان
- **django-celery-beat**: زمان‌بندی وظایف
- **django-celery-results**: ذخیره نتایج وظایف

### API Documentation
- **drf-spectacular**: تولید OpenAPI Schema
- **drf-yasg**: رابط کاربری Swagger

### Utilities
- **python-environ**: مدیریت متغیرهای محیطی
- **openpyxl**: کار با فایل‌های Excel
- **Pillow**: پردازش تصاویر

## نکات مهم برای توسعه‌دهندگان

### 1. الگوی طراحی سرویس:
```python
# همیشه منطق تجربی در سرویس‌ها باشد
class OrderService:
    def create_order(self, user, cart):
        # منطق تجاری
        pass
```

### 2. مدیریت خطا:
```python
# استفاده از Exceptionهای سفارشی
class InsufficientStockError(Exception):
    pass
```

### 3. لاگ‌گذاری:
```python
# استفاده از لاگرهای اختصاصی
logger = logging.getLogger('shop.services.product_list')
logger.info("Product list retrieved")
```

### 4. تراکنش‌ها:
```python
# استفاده از atomic برای عملیات حساس
from django.db import transaction

with transaction.atomic():
    # عملیات دیتابیس
    pass
```
